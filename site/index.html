Open source · self-hosted · alpha

Plan with a strong model.
Code with a cheap one.

pirs is a coding agent you run yourself. It edits your repo and runs tests — and unlike most agents, you can split work across two models and program how it behaves with short scripts.

Get started See the numbers

Best fit if you care about cost control, custom tools/policy, or multi-model workflows. If you want a polished all-in-one cloud IDE agent, start with those instead.

Why people pick pirs

Not “another chat that edits files.” Three reasons it exists.

Cost shape

Two models, one task

Hard thinking (plan, review) on a strong model. The long tool loop (read, edit, test) on a cheap one. You pay for judgment where it matters.

  • --model = executor
  • --plan-model = planner / reviewer
  • Strategies define the playbook
  • weak-drive: 34/50 · mono: 29/50

Control

Script the agent

Drop Rhai files into the project. No rebuild. Encode team rules once — every run obeys them.

  • Add tools (internal APIs, checklists…)
  • Block shell you never want
  • Hook context, stop, steering
  • Override strategies per repo
  • Optional packs: guards, goals, review…
fn on_tool_call(id, name, args) {
  if name == "bash"
      && args.command.contains("rm -rf") {
    return #{ block: true,
              reason: "not allowed" };
  }
  ()
}

Who it’s for

Good fit

  • You already juggle multiple model APIs and care about $/task
  • You want policy as code (guards, tools, plan-first workflows)
  • You’re fine with a terminal-first, self-hosted tool
  • You care whether strategies actually move scores

Probably not

  • You want the least-friction cloud agent with zero config
  • You need a full multi-app chat bot (Slack/Discord/… at product depth)
  • You’re not willing to set an API key and try one dual-model command

Get started in three steps

One recommended path. Details live on examples.

1

Install

curl -fsSL https://raw.githubusercontent.com/xmonader/pirs/main/scripts/install.sh | sh

Or git clone + cargo build --release. Puts binaries on your PATH (default ~/.local/bin).

2

Add a key

mkdir -p ~/.pirs
echo 'OPENAI_API_KEY=sk-…' >> ~/.pirs/secrets.env
# Anthropic, DeepSeek, OpenRouter, … also work
3

Run on a real repo

cd your-project

# Interactive
pirs --mode tui

# Recommended for real bugs (two models)
pirs --model deepseek-v4-flash --plan-model deepseek-v4-pro \
  --strategy weak-drive "fix the failing tests"

Unattended / CI: add --autonomy full so bash and tests can run. Default edit autonomy blocks the shell on purpose.
