Control

Program the agent without forking it

Most agents only take prompts. pirs also takes scripts: tools, denials, and workflows as files in the repo. Written in Rhai — small, embeddable, no rebuild.

What you can do

  • Add a tool the model can call (e.g. hit your internal API).
  • Block commands you never want run (rm -rf, force-push, …).
  • Change the workflow — plan first, then code, then review (see strategies).
  • Turn packs on or off with a profile so sessions stay light.

Where files go

  • .pirs/extensions/ in a project — team policies and tools
  • ~/.pirs/extensions/ — your personal packs
  • .pirs/strategies/name.rhai — override or invent a strategy

Example: add a tool

Save as .pirs/extensions/word_count.rhai:

register_tool("word_count", "Count words", #{
    type: "object",
    properties: #{ text: #{ type: "string" } },
    required: ["text"]
});

fn tool_word_count(args) {
    `${args.text.split(" ").len()} words`
}

Use backtick strings for ${…} interpolation. The model can call word_count like any built-in tool.

Example: block bad bash

fn on_tool_call(id, name, args) {
    if name == "bash" && args.command.contains("rm -rf") {
        return #{ block: true, reason: "not allowed" };
    }
    ()
}

Scripts can only make things stricter. Dangerous patterns are also blocked in Rust even if you remove the pack.

Shipped packs

pirs comes with many optional packs already (guards, goals, review helpers, sandboxes, …). You don’t need to write any of that yourself unless you want to. Browse them in the repo: extensions/.
