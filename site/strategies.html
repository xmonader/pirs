How the agent works a task

Strategies

A strategy is the step-by-step playbook pirs follows for a task. Pick one with --strategy …. Numbers below are from our own runs — not marketing benchmarks from other tools.

Measured results

Same 50-bug SWE-bench Lite set, strict protocol: the agent never sees the hidden test patch. Executor model is deepseek-v4-flash unless noted.

Strategy Models Strict SWE Lite Process suite
weak-drive flash + pro 34/50 (68%) 4/5
plan-exec flash + pro — 4/5
no strategy (naive) flash only 31/50 (62%) 3/5
monolithic flash only 29/50 (58%) 3/5
mono + shadow verify flash only 32/50 (64%) —
spark-ember flash only 4/5 smoke · 9/20 batch —

Process suite = shrimpswe (5 multi-step coding traps: multi-site, red herring, needle, broken env, moving target). Peer harness on the same strict SWE set: pi 27/50.

Caveats: keep-green regression sample is capped (default 40 tests); the 34/50 weak-drive run predates a stricter git scrub — full notes in LEADERBOARD.md. Weak-drive is the only full-50 row that also uses a second (strong) model for plan/review.

What that means in practice

  • weak-drive (34/50, 4/5) — best measured default for real bugs. Dual model pays off: +5 vs mono on strict SWE, +1 vs naive/mono on the process suite.
  • plan-exec (4/5 process) — same process score as weak-drive on shrimpswe; we haven’t published a full strict-50 for it yet.
  • monolithic / naive (~29–31/50, 3/5) — fine for small tasks; lose more on multi-step traps (red herring, broken env).
  • spark-ember — partial data only (5 + 20 instance slices), not a full-50 score.

weak-drive 34/50 · 4/5

Strong model plans → cheap model codes → strong model reviews → cheap model fixes if needed. Flags: --model (cheap) + --plan-model (strong).

2

plan-exec 4/5 process

Plan once, then execute. Dual models without the full review loop.

3

monolithic 29/50 · 3/5

One model, one growing loop. Simple; weaker on hard multi-step tasks.

pirs --model deepseek-v4-flash --plan-model deepseek-v4-pro \
  --strategy weak-drive "fix the failing tests"

What weak-drive does

  1. Plan — strong model reads the code and writes a concrete plan (no edits).
  2. Execute — cheap model makes the changes and runs tests.
  3. Review — strong model says approve or revise.
  4. Fix up — if revise, cheap model applies the recovery plan. If approve, this step is skipped.

If the cheap model gets stuck mid-task, it can also ask the strong model for help (hybrid mode — on by default for this strategy).

Also available

  • plan-critic-exec — plan, then a critic pass, then execute (no full-50 score yet)
  • spark-ember — explore in parallel, then code (4/5 smoke, 9/20 follow-up batch)
