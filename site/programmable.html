Programmability

A coding agent you can program with Rhai

Mechanism stays in Rust (loop, tools gate, providers). Policy lives in scripts — embedded packs, project overrides, and your own .rhai files. No rebuild to change how the agent behaves.

What you can script

Custom tools

register_tool + fn tool_<name> — the model can call your tools like any built-in.

Lifecycle hooks

on_tool_call, on_context, on_should_stop, on_steering, on_follow_up, on_event.

Slash commands

register_command + fn cmd_<name> — REPL / TUI commands you define.

Strategies

Multi-phase maps: plan → exec → review. Built-ins are Rhai; projects can shadow them.

Profiles & packs

Select which extension packs load (packs: "*" or an explicit list).

Host APIs

exec, fs_read/fs_append, state_get/state_set, checkpoints, skills index, and more.

Where scripts live

Kind Paths Notes
Extensions .pirs/extensions/ · ~/.pirs/extensions/ Project / user packs; win on tool-name collisions
Bundled packs extensions/*.rhai (embedded) Loaded via profile packs
Strategies .pirs/strategies/<name>.rhai Shadows built-in of the same name
Profiles .pirs/profiles/<name>.rhai Which packs + default strategy
Safety rule: Rust hard denials (catastrophic shell, plan-profile gates) cannot be loosened from packs. Packs may only add denials and policy.

Example: custom tool + policy hook

Drop this under .pirs/extensions/word_count.rhai (or ~/.pirs/extensions/):

Register a tool and block bad bash

Backtick strings with ${…} for interpolation (not double-quoted templates).

register_tool("word_count", "Count words", #{
    type: "object",
    properties: #{ text: #{ type: "string" } },
    required: ["text"]
});

fn tool_word_count(args) {
    `${args.text.split(" ").len()} words`
}

fn on_tool_call(id, name, args) {
    if name == "bash" && args.command.contains("rm -rf") {
        return #{ block: true, reason: "rejected by policy" };
    }
    ()
}

Example: custom strategy (map shape)

Strategies are Rhai maps with phases. Readonly phases pin to --plan-model; full phases use --model. See the full catalog on the strategies page.

.pirs/strategies/my-plan.rhai

Templates: {issue}, {targets}, {prev}, {prev_0}, {verdict}

#{
    name: "my-plan",
    hybrid: false,
    phases: [
        #{
            scope: "readonly",
            system: "You plan only. Do not edit.",
            prompt: "Plan a fix for:\n{issue}\n\nTests:\n{targets}",
        },
        #{
            scope: "full",
            system: "Execute the plan. Verify with tests.",
            prompt: "Issue:\n{issue}\n\nPlan:\n{prev}\n\nImplement now.",
        },
    ],
}
